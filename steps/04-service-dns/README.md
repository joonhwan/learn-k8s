# 04단계 — 서비스와 클러스터 DNS

> **이 단계의 문서는 아직 작성되지 않았습니다.** 진도가 여기에 도달하면, 그동안
> `PROGRESS.md`에 기록된 막혔던 지점을 반영해서 작성합니다. 아래는 다룰 범위입니다.

## 이 단계를 마치면

- Service 의 종류를 구분하고 각각 언제 쓰는지 설명할 수 있습니다.
- Service 와 Pod 이 레이블 셀렉터로 이어지는 과정을 Endpoints 로 확인할 수 있습니다.
- 클러스터 안에서 이름으로 다른 서비스를 찾을 수 있습니다.

## 다룰 내용

- Pod IP 가 바뀌는 문제를 Service 가 어떻게 푸는가 (안정된 가상 IP)
- ClusterIP, NodePort, LoadBalancer, headless Service 의 차이
- 셀렉터 → EndpointSlice → 실제 Pod 으로 이어지는 연결
- CoreDNS 와 이름 규칙 (`서비스명.이름공간.svc.cluster.local`)
- kube-proxy 가 트래픽을 나누는 방식
- 준비되지 않은 Pod 이 대상 목록에서 빠지는 과정

## 앞 단계에서 남겨 둔 질문

- **03단계**: 롤링 업데이트 중에 서비스가 정말 끊기지 않는지 확인하지 못했습니다. 트래픽을
  보낼 안정된 주소가 없었기 때문입니다. 이 단계에서 Service 를 붙인 뒤 갱신하면서
  응답이 끊기는지 실제로 측정합니다.
- **02단계**: Pod 을 다시 만들면 IP 가 바뀌는 것을 확인했습니다. 그 문제의 해답이 이
  단계에 있습니다.
