# 06단계 — 설정과 비밀값

> **이 단계의 문서는 아직 작성되지 않았습니다.** 진도가 여기에 도달하면, 그동안
> `PROGRESS.md`에 기록된 막혔던 지점을 반영해서 작성합니다. 아래는 다룰 범위입니다.

## 이 단계를 마치면

- ConfigMap 과 Secret 을 환경 변수와 볼륨 두 방식으로 주입하고, 차이를 설명할 수 있습니다.
- Secret 이 암호화가 아니라는 사실을 직접 확인하고, 그럼에도 왜 구분해서 쓰는지 설명할 수
  있습니다.

## 다룰 내용

- 설정을 이미지에 굽지 않고 분리하는 이유
- ConfigMap 주입의 두 방식: `env`·`envFrom` 과 볼륨 마운트
- 두 방식의 결정적 차이: **환경 변수는 컨테이너를 다시 시작해야 바뀌고, 볼륨으로 마운트한
  파일은 잠시 뒤 저절로 갱신된다**
- Secret 의 실체 (base64 는 인코딩이지 암호화가 아니다). etcd 암호화와 외부 비밀값 관리로
  가는 방향
- Downward API 로 Pod 자신의 정보(이름, IP, 노드)를 주입하기
- 설정이 바뀌었을 때 Pod 을 다시 굴리는 방법 (해시를 주석에 심는 관행)

## 실습 앱에 준비된 것

`app/` 의 앱에는 이 단계를 위한 엔드포인트가 있습니다.

- `GET /env` — 환경 변수 전체를 출력합니다. 주입이 실제로 되었는지 확인합니다.
- `GET /file?path=...` — 파일 내용을 출력합니다. 볼륨 마운트를 확인합니다.
- `MESSAGE` 환경 변수 — 응답에 실려 나옵니다.
- `POD_NAME`·`POD_IP`·`POD_NAMESPACE`·`NODE_NAME` — Downward API 로 주입하면 응답에
  채워집니다.

`/env` 와 `/file` 은 Secret 의 내용까지 그대로 드러냅니다. "Secret 은 암호화가 아니다"를
확인하기 위한 장치이며, 실제 서비스에 두면 안 되는 엔드포인트입니다.
